Rush Monorepo Architecture

Enterprise workspace coordinator for managing independent application submodules.

The Multi-Repo Friction

  • • Managing multiple decoupled applications separately creates version mismatches and duplicate packages.
  • • Individual deployments consume excessive engineering time and require separate cloud hosting per service.

The Rush Monorepo Solution

  • ✓ Consolidates external Git repositories into a single umbrella workspace using Git submodules.
  • ✓ Centralizes dependencies via pnpm, provides selective cached builds, and packages apps for a single-pod deployment.

Code Sourcing: Git Submodules

Keeping independent developer repositories linked into a centralized parent workspace.

Individual apps (app-react-one, app-react-two, nestjs-demo) stay in their own independent Git repositories so external teams work isolated. A custom sync script pulls and coordinates them into the monorepo.

⚡ The Sync Script Handles:

  • • Reads app configurations from common/config/projects.json.
  • • Auto-adds or initializes submodules into apps/<name>.
  • • Tracks specific branches (main, dev, master) or pinned commits.
  • • Verifies clean working directories to prevent accidental overwrites.

📦 Then Rush Handles:

  • • Registers all submodules declared in rush.json.
  • • Links all projects into a unified pnpm virtual store.
  • • Enforces global version policies across all sub-projects.
  • • Exposes rush sync as a native developer command.

Centralized Dependencies & Build

Eliminating dependency drift, broken versions, and repeated build times.

Capability Without Rush (Independent) With Rush + pnpm
Package Storage Duplicate node_modules in every app folder (eating gigabytes of disk). Single central pnpm store in common/temp using symlinks.
Version Consistency Version drift: Team A uses React 18, Team B uses React 19 leading to runtime breakage. Single pnpm-lock.yaml enforces strict version rules across all apps.
Compilation (rush build) Manual builds per repo; no coordination of inter-dependent libraries. Topological parallel execution with smart caching; skips unchanged apps automatically.
Build Artifacts Scattered outputs across unstandardized build folders. Uniform dist/ directories ready for production packaging.

Selective Deployment: deploy.json

Extracting production-ready applications and dropping heavy developer tools.

The Scope Filter

Rush reads common/config/rush/deploy.json to determine exactly which subset of apps are bundled: 

{
  "deploymentProjectNames": [
    "app-react-one"
  ],
  "projectSettings": [
    {
      "projectName": "app-react-one",
      "additionalProjectsToInclude": [
        "app-react-two"
      ]
    }
  ]
}

What It Delivers

  • ✓ Zero devDependencies: Throws away TypeScript compilers, linters, and Jest test runners.
  • ✓ Resolves Symlinks: Converts pnpm symlinks into real files so Docker never fails.
  • ✓ Clean Target: Exports pure deployable code to common/deploy.
Result: Container sizes drop from ~3 GB to under 30 MB.

Automated Parallel Docker Builder

Custom command rush docker:build with concurrency throttling and git diff detection.

Command
rush docker:build
Single root command
Parallel Limit
MAX_CONCURRENT = 2
Prevents CPU/RAM deadlock
Selective Mode
--changed-only
Builds only modified apps

1. Git Diff Scanning

Detects modified files and submodule pointer updates. If only app-react-two was touched, app-react-one is automatically skipped.

2. Registry Push (--push)

Builds and uploads directly to GitHub Container Registry (ghcr.io). Existing image tags are cleanly replaced with zero manual intervention.
